# Специфікація продукту

DriveM CRM централізує операції магазину автозапчастин. Склад CRM визначає доступність до продажу, каталог визначає внутрішню ідентичність товару, кожен канал має власну публікацію й ціну. Зовнішні замовлення можуть надійти після того, як запас уже зарезервовано в іншому каналі. Система зберігає таке замовлення й показує конфлікт менеджеру.

## Модулі

| Модуль | Основна дія |
| --- | --- |
| Головна | Переглянути замовлення до опрацювання, дефіцит, збої синхронізації та показники за період |
| Замовлення | Прийняти, зіставити товар, зарезервувати, відвантажити або скасувати |
| Каталог | Знайти деталь за внутрішнім артикулом, брендом чи номером виробника, керувати публікаціями |
| Склад | Прийняти товар, перемістити, провести інвентаризацію, перевірити резерви й рухи |
| Ціноутворення | Розрахувати й затвердити ціну по каналах, бачити історію та помилки публікації |
| Клієнти | Знайти клієнта й пов'язані замовлення, керувати контактами в межах дозволів |
| Логістика | Зібрати відправлення, зберегти ТТН, обробити видачу й повернення |
| Фінанси | Звірити оплати, повернення, комісії та собівартість, розрахувати операційну маржу |
| Інтеграції | Налаштувати обліковий запис, переглянути стан, повторити дозволені операції |
| Налаштування | Керувати користувачами, ролями, складами, каналами й параметрами бізнесу |

## Робочі сценарії

1. Оператор створює або імпортує картку деталі. Внутрішній SKU унікальний. Бренд і номер виробника допомагають знайти збіги, неоднозначні зіставлення підтверджує оператор. Окремі публікації можуть посилатися на одну картку.
2. Менеджер бачить нове замовлення та результат резервування. Якщо позиція невідома або запасу бракує, замовлення потрапляє в чергу винятків. За замовчуванням резервуються всі рядки разом. Розподіл між складами і часткове відвантаження запускаються явною дією.
3. Комірник перевіряє склад і резерв, фіксує фактичне відвантаження та бачить історію. Скасування звільняє невикористаний резерв. Повернення грошей і фізичне повернення оформлюються окремо.
4. Менеджер затверджує зміну ціни. Дозвіл на передачу, цільова ціна й остання підтверджена ціна каналу мають окремі стани. Фінансист бачить первинні суми замовлення та джерело кожної фактичної комісії.

## Інтерфейс

Українська мова, форматування сум через `uk-UA` і UAH, бізнес-періоди в `Europe/Kyiv`. Білий фон `#FFFFFF`, основний акцент `#FF0005`, другорядна поверхня `#FFF2F2`. Використати `DriveM.svg` після отримання оригіналу. Для кнопок і повідомлень перевіряти WCAG 2.2 AA, особливо текст поверх червоного. Критичні стани дублювати текстом або піктограмою.

Постійна навігація за модулями, таблиці з фільтрами та сторінками, деталізація з історією дій. Перед масовим імпортом, коригуванням залишків або зміною цін показувати наслідки й вимагати підтвердження. Опрацювати порожній стан, завантаження, відсутність дозволу, конфлікт даних і повтор запиту. Передбачити клавіатурну навігацію, видимий фокус і доступні назви полів. KeyCRM слугує орієнтиром для операційних сценаріїв. Візуальна система DriveM має власні компоненти, кольори й композицію.

## Межі першого релізу

Один бізнес, кілька складів і кілька облікових записів каналів. Ізоляція даних за організацією закладається в схему. Облік окремих серійних номерів, наборів і фіскалізація потребують окремого проєктування. Фінансовий модуль надає управлінську аналітику. Правила податків, розподілу витрат і межі бухгалтерського обліку затверджуються перед реалізацією.
