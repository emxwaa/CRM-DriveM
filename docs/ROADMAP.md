# План розробки та критерії готовності

| Етап | Обсяг | Приймання |
| --- | --- | --- |
| 1. Проєктування | Вимоги, архітектура, дані, інтеграційні контракти, план | Усі сім документів наявні. Наслідки для запасу, грошей і безпеки описані. Відкриті рішення й обмеження зафіксовано |
| 2. Основа | Next.js, TypeScript, Tailwind CSS, shadcn/ui, Docker, PostgreSQL, Supabase Auth, Redis, BullMQ, GitHub Actions. Навігація й UI-токени | Чиста копія запускається за інструкцією. Міграції проходять на порожній базі. CI перевіряє збірку, типи й тести. Перевірено ізоляцію організацій, права доступу та повторну доставку завдань |
| 3. Каталог, склад та імпорт | Товари, склади, публікації, рухи, резерви, імпорт через staging | Дві паралельні спроби зарезервувати останню одиницю дають одне успішне резервування. Повтор ідентичної команди не створює рухів. Збій між записами відкочує транзакцію. Звірка сходиться. Усі чотири формати проходять сухий прогін і повторне застосування |
| 4. Замовлення, клієнти й логістика | Ручні замовлення, зіставлення товарів, дефіцит, резерв, часткове відвантаження, скасування і повернення | Наскрізний сценарій проходить від створення до відвантаження й приймання повернення. Повторне відвантаження та надлишкове повернення блокуються. Доступ до контактів перевірено |
| 5. Ціни, фінанси та Dashboard | Версії цін, знімки собівартості, оплати, комісії, сторно, аналітика | Фінансист погодив правила. Контрольні приклади покривають округлення, часткові операції, повернення, сторно та межі періоду в Europe/Kyiv. Звіт звіряється з проведеннями, зміна каталожної ціни не змінює історію |
| 6. Інтеграції з читанням | Перевірка документації та адаптери Prom.ua, Rozetka, Епіцентр по одному | Для кожного каналу задокументовані доступні можливості й обмеження. Контрактні тести перевіряють помилки, пагінацію, дублікати, запізнілі події та відновлення курсора. Дозволене читання підтверджено на погодженому обліковому записі. Запис вимкнено |
| 7. Контрольований запис і запуск | Окреме погодження, перевірка в тестовому режимі, пілот, моніторинг і процедури відновлення | Для кожного дозволеного каналу перевірено ліміти, відновлення черги, невизначений результат, зупинку та звірку. Відновлення резервної копії підтверджено. Навантажувальні перевірки відповідають погодженим бізнес-обсягам |

## Залежності між етапами

До реалізації вартісних складських рухів на етапі 3 погодити політику оцінки запасів і правила початкового завантаження. Пул собівартості потрібен на етапі 3, а знімки собівартості — вже при першому відвантаженні на етапі 4. Етап 5 додає проведення та звіти на основі цих фактів. Реальний складський запуск допускається після перевірки фінансових наслідків і звірки початкових залишків.

## Ризики та залежності

| Ризик | Дія та умова переходу |
| --- | --- |
| Одночасні продажі за застарілим залишком | Блокування в CRM, буфер по каналу, опрацювання дефіциту. Перед пілотом виміряти затримку й погодити буфер |
| Дублікати, втрата черги та невідомий результат запиту | Транзакційний outbox, ідемпотентність, стійкі записи результатів, звірка. Перевірити зупинку воркера й відновлення Redis |
| Нестабільні або непідтверджені API | Підтвердити можливості для кожного акаунта. Канал із непідтвердженим записом залишається в погодженому режимі читання або ручного обміну |
| Помилки імпорту та зіставлення деталей | Попередній перегляд, версії й ручне підтвердження конфліктів. Звірити початкові залишки перед переходом на CRM |
| Невірна маржа та податкові розбіжності | Затвердити політику собівартості, момент визнання продажу, комісії, податки й закриття. Звірити на контрольному періоді |
| Витік контактів або токенів | Мінімальні права, RLS, ізоляція середовищ, ротація секретів і очищення логів. Перевірити доступ і порядок реагування |
| Втрата даних або деградація продуктивності | Погодити прогноз навантаження, RPO, RTO, терміни зберігання та цільовий час оновлення каналів. Перевірити відновлення й виміряти лаг |
| Відсутні вхідні матеріали | Потрібні оригінал DriveM.svg, приклади файлів імпорту без персональних даних та матриця доступів. Для інтеграцій потрібен підтримуваний доступ до документації та погоджені акаунти |
